# AGENTS.md — CatCare Wiki AI 開發規則

> 本文件是專案的持續開發規範。任何 AI 助手在新增、修改程式碼或文章前，應先閱讀本文件及 `SPEC.md`。

## 1. 專案目的與界線
- 建立面向一般貓咪飼主的繁體中文照護百科。
- 網站內容以清楚、易讀、可信為原則；不得將一般照護資訊當成個別貓咪的診斷或治療處方。
- 第一版只做靜態單頁式網站，不得自行新增後端、資料庫、登入、付款、留言或聊天功能。

## 2. 技術與架構規則
- 使用 HTML5、CSS3、原生 JavaScript，網站入口為根目錄 `index.html`。
- `css/style.css` 存放共用樣式；`js/app.js` 管理畫面狀態、搜尋及分類；`js/articles.js` 管理文章索引載入及 Markdown 渲染。
- `articles/*.md` 存放獨立文章；`data/articles.json` 是唯一文章索引來源。
- 不得在首頁 HTML 手動硬編碼文章卡片。文章卡片必須由索引資料產生。
- 所有資源使用相對路徑，以相容 GitHub Pages 專案路徑。
- 文章讀取失敗時顯示友善提示；不得讓整頁空白。
- 不得把未經清理的 Markdown 原始 HTML 直接注入頁面；若使用 Markdown 解析器，必須關閉原始 HTML 或經過安全清理。

## 3. 視覺與互動規則
- 使用奶油白 `#FFF9F0`、鼠尾草綠 `#8BAF9A`、深灰 `#303A35` 為主色。
- 版面溫馨可愛、圓角卡片、留白充足；同類元件沿用共用 CSS，不要為每篇文章重做設計。
- 手機、平板、桌面都需可閱讀；搜尋、分類、文章切換須可使用鍵盤操作。
- 使用語意化 HTML、可辨識的焦點樣式及圖片 `alt`；避免只用顏色表示狀態。
- 單頁式網站的「文章閱讀」為同一 `index.html` 內的視圖切換，而非每篇文章各建立一個 HTML。

## 4. 文章分類與命名
分類代碼只能使用：
- `health`：健康疾病
- `nutrition`：飲食營養
- `behavior`：行為觀察
- `daily-care`：日常照護

檔案名稱一律使用英文小寫與連字號，例如 `cat-acne.md`。`slug` 必須唯一，原則上與檔名（去除 `.md`）一致。文章標題、摘要及內文使用台灣慣用繁體中文。

## 5. 文章標準格式
每篇 Markdown 至少使用以下結構：

```markdown
# 文章標題

簡短摘要，說明這篇文章能幫助飼主理解什麼。

## 主題介紹

## 常見原因或背景

## 觀察重點

## 照護建議

## 何時尋求獸醫協助

## 參考資料
- 來源名稱、文章標題及可查證網址（如有）

> 本文僅供一般照護資訊參考，不能取代獸醫診斷與治療。
```

- 若某章節不適用，保留標題並用簡短文字說明，不得硬編造資訊。
- 不能杜撰研究、醫療來源、引用網址或專家意見；無法查證時明確註明「待查證」。
- 避免提供具體處方藥劑量、未經證實的療法或保證治癒的說法。
- 出現呼吸困難、昏厥、無法排尿等急症警訊時，應明確建議立即尋求獸醫協助。

## 6. articles.json 格式
`data/articles.json` 必須是有效 JSON 陣列，單筆資料範例：

```json
{
  "slug": "cat-acne",
  "title": "貓咪黑下巴是什麼？",
  "category": "health",
  "summary": "認識貓咪下巴黑色顆粒的常見原因與照護重點。",
  "tags": ["皮膚", "黑下巴", "清潔"],
  "file": "articles/cat-acne.md"
}
```

- 不得重複 `slug` 或 `file`。
- `file` 必須指向實際存在的 `.md` 文件，且不得使用 `../` 跳脫專案路徑。
- 搜尋至少涵蓋 `title`、`summary`、`tags`；分類依 `category` 篩選。

## 7. AI 新增文章的標準流程
收到「新增一篇文章」要求時，必須依序：
1. 先閱讀 `AGENTS.md`、`SPEC.md`、現有 `data/articles.json` 與一篇既有文章。
2. 確認文章分類、英文 slug、是否已存在相同主題；避免重複新增。
3. 依第 5 節的統一模板建立 `articles/<slug>.md`。
4. 將完整文章資訊加入 `data/articles.json`；保留其他文章資料。
5. 不修改首頁 HTML 來硬塞文章卡片；由既有資料驅動機制顯示新文章。
6. 驗證 JSON 格式正確、Markdown 檔案存在、首頁可搜尋到新文章、分類正確、文章能正常開啟。
7. 回報新增檔案、修改檔案及驗證結果；無法驗證時如實說明。

## 8. AI 修改程式的標準流程
- 修改前先檢查既有檔案及功能，盡量採用最小必要變更。
- 不得任意刪除既有文章、分類、功能或改變專案架構。
- 共用樣式統一放在 `css/style.css`，避免重複、衝突的 CSS。
- 新增互動功能須保留搜尋、分類、文章閱讀及返回功能。
- 不得加入需要 API Key 的服務；不可把密鑰寫入前端。
- 完成後檢查瀏覽器主控台錯誤、手機版排版及 GitHub Pages 相容性。

## 9. 部署與驗收
- 網站必須能透過 GitHub Pages 靜態託管。
- 本機測試使用 HTTP server，不依賴直接雙擊 `index.html` 的 `file://` 模式。
- 驗收項目：首頁可開、至少三篇文章可讀、搜尋及分類正常、手機版可用、新增文章不需修改首頁 HTML。
- GitHub Repository 根目錄需保留 `AGENTS.md`、`SPEC.md`、`README.md`。

## 10. 擴充示範任務
「請先閱讀 AGENTS.md，新增一篇『貓咪日常梳毛與清潔』文章，依既有格式建立 Markdown、更新 articles.json，並驗證首頁分類與搜尋功能，不要修改既有文章或改動視覺風格。」
